# Cover 歌词整理

原曲解析使用同一对 RunningHub 应用：国内站 `2107851228599382017`，国际站 `2107851452228509697`。输入仍然只发送节点 30 的音频。

工作流输出：节点 31 保存 ABC，节点 34 保存 ASR 原歌词，新增节点 40 SaveText 接节点 38 的第三个输出 `timestamps`，文件前缀 `Lyrics_Timestamps`，格式 `md`。节点 37 使用 `Qwen/Qwen3-ForcedAligner-0.6B` 并启用，节点 38 开启 `return_timestamps`。两个应用都需要发布更新；只启用时间戳而不连接保存节点，API 不会返回时间戳文件。

网站保存 `inferredLyrics` 原文和规范化的 `lyricsTimestamps`，然后使用服务端既有 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 整理为独立的 `structuredLyrics`。提示词要求只增加换行与段落标签；服务端核对除空白和合法段落标签外的全部内容及顺序，拒绝改词、删词和省略重复歌词。主歌/副歌等标签是 AI 推测，不保证还原音乐结构。

无时间戳时按文本整理并显示提示；无法解析时间戳时不阻断 ABC/歌词保存。DeepSeek 失败也保留原文，解析任务仍完成，可单独重试整理。纯音乐无歌词时跳过整理。

`POST /api/generations/:id/lyrics` 只整理当前用户已保存的 Cover 解析结果，不读取客户端提供的歌词，不重复提交 RunningHub。数据库租约防止并发整理，30 秒内已有的成功结果直接复用。刷新及普通结果同步不会重新调用 DeepSeek。

Cover 编辑框优先载入整理歌词，用户已修改的歌词不被异步返回覆盖。界面只展示解析状态和可编辑歌词，已移除整理版、ASR 原文、ABC 的重复折叠展示，以及手动整理和时间戳下载按钮。后台继续保存原文、整理版、ABC 和时间戳，自动解析与整理不受影响；下载方案 JSON 中保留这些数据。

翻唱设置与方案预览先显示歌词，再显示音乐风格。歌词下方的语言选择和“翻译歌词”复用创作空间的 DeepSeek 译配接口及九种语言，支持 5000 字以内的歌词并校验原有段落标签。译配只更新当前编辑框，解析原文及整理版保持独立。请求期间修改输入、清空表单或切换来源时，旧译配结果不覆盖新输入。方案保留所选语言，继续编辑时恢复。
